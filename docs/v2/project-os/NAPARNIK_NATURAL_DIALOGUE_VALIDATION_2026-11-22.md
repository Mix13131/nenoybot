# Напарник: включённый по умолчанию диалог без команд

Дата: 2026-11-22. PR #171; исходный checkpoint:
`e0b89488b1967d7a7e8826636c8bde8bee8ac100`.

## Основание изменения

Владелец прямо заменил прежний продуктовый сценарий: все возможности работают
сразу в настроенной группе; не нужны отдельные личные включения, лимит одного
вопроса/эксперимента или подтверждение публикации обзора. Бот сам выбирает момент
и форму участия. Старый протокол проверки сохранён отдельно как история, а
[runbook](../NAPARNIK_PILOT.md) описывает действующее поведение.

## Реализованное изменение

- При первом сообщении до archive capture создаётся group_default policy с
  `actor_user_id=NULL`. Первое сообщение сразу архивируется и обрабатывается.
  Граница — активация темы. Существующие личные остановки не переопределяются.
- Основной интерфейс — обычный разговор. Адресные фразы останавливают, возобновляют,
  удаляют память и вызывают трек без дополнительного подтверждения. Старые slash
  aliases совместимы, но меню команд пустое. UUID не нужен в обычном сценарии.
- Извлечение фактов и поиск больше не отсеивают короткое продолжение как «не отчёт».
  Финальная фаза выбирает SILENCE/RESPOND после разрешённой памяти и диалога.
- RESPOND содержит произвольное число сообщений и экспериментов в техническом
  byte/token budget. Длинный текст делится по 4096 UTF-16 единиц без потерь.
- Часть ответа отправляется только после успешной предыдущей. Каждая часть заново
  проверяет доступ и актуальность источников. Timeout, edit или revoke отменяют
  оставшиеся части без слепого повтора. Эксперимент становится offered после
  доставки связанного сообщения. Одинаковые предложения используют одну карточку.
- Действительно доставленные ответы сохраняются как собственный assistant-контекст
  с raw-source зависимостями; слова бота не становятся фактическими свидетельствами
  действий пользователя. Контекст строго разделён по группе, теме и автору.
- Отзыв истории, забывание, удаление трека и изменение источника физически очищают
  соответствующий контекст. Старый callback не может его восстановить. Остановка
  автоответов сохраняет разрешённый контекст для прямого продолжения разговора.
- Заполненная конфигурация отдельного бота включает runtime/AI без дополнительных
  flags. Пустая среда остаётся неактивной; финансовые параметры AI обязательны.
  Явные операторские выключатели 0 сохраняются.
- Новые миграции 0013/0014 аддитивны; прежние миграции не переписаны. Stage A,
  денежный pre-call резерв, исходные scope-границы и ранее исправленные гонки
  удаления/ранней правки сохранены.

## Найденные и устранённые проблемы

Промежуточные lifecycle failures указывали на старые ожидания personal disclosure,
обязательного opt-in, подтверждения обзора, единственного сообщения и прежнего
текста удаления. Direct-only сценарии теперь сначала явно отключают память;
проверяется отсутствие живого текста, при этом технические tombstones допустимы.

Независимое чтение обнаружило дополнительный дефект continuity: repo отбирал
свежие реплики по textbytes, а второй JSON/proof budget в engine обходил результат
от старого к новому. При переполнении исчезала последняя реплика бота. Исправление
отбирает newest-first и возвращает модели хронологический порядок. Регрессия
проверяет именно различие text budget и JSON/proof overhead.

## Границы доказанности

Подтверждена механика разговора, хранения, источников, доставки и удаления.
`real_model_quality_measured=false`: fake-провайдер не доказывает уместность момента,
тон, понимание свободной речи или полезность советов реальной модели. Проверка
цитат не доказывает истинность каждого предложения свободного сгенерированного
ответа. Для quality-набора подготовлено 20 синтетических сценариев.

Детерминированный feedback понимает короткие фразы, связанные с реальным
предложением через reply или единственный подходящий эксперимент. Произвольная
фраза вроде «попробую второй», если два предложения в одном сообщении, может
продолжить AI-диалог без изменения статуса конкретной карточки. Это не заявляется
как проверенное автоматическое сопоставление.

Реальный бот, username, группа/topic IDs и защищённые credentials не подключены;
production, Railway, merge и действующий НеНой не изменены. Финальные SHA,
GitHub CI и внешнее ревью фиксируются в PR #171 после публикации проверенного дерева.
