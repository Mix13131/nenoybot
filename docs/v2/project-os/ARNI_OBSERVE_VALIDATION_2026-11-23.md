# Арни: сбор статистики без денежного потолка

## Решение и граница изменения

23 ноября 2026 года владелец указал: «пока не ограничиваем его, чтобы собрать
статистику». Это отменяет необходимость выбрать дневную сумму перед первым
запуском. Введён явный `COACH_AI_BUDGET_MODE=observe`: cap равен NULL, денежной
квоты и квоты числа сообщений нет. Совместимый `capped` остаётся режимом по
умолчанию для конфигураций, которые не выбрали наблюдение явно.

База этой проверки — дерево `c183d5f17e17952be0e776831a797daa4f6c9955`, опубликованное
в PR #171 как commit `587d6b1204c9363a1ded98b8d950ed0a92dce171`. Stage A #169 принят
ранее. Изменения legacy `app/` и `tests/` не входят в этот шаг.

## Что изменилось

- Миграция 0016 добавляет режим учёта и nullable cap с CHECK согласованности.
- Все попытки фиксируются до AI-вызова; дубликаты operation ID не оплачиваются
  повторно. Подтверждённый usage и неопределённые резервы остаются раздельными.
- `usage_stats` и `coach_admin stats` дают агрегаты токенов, стоимости, задержек,
  ошибок, молчания и назначений операций. Worker пишет сводку каждые пять минут.
  Содержимое переписки, идентификаторы участников и credentials туда не входят.
- `bootstrap-database` явно создаёт одну отдельную логическую БД на существующем
  PostgreSQL. Нельзя использовать исходную, системную или чужую базу. Существующие
  таблицы, данные, владельцы и настройки не меняются.
- Пара `COACH_DATABASE_BASE_URL + COACH_DATABASE_NAME` сохраняет экранирование
  credentials при выборе отдельной базы; конфликт с прямым URL отклоняется.
- `smoke-ai` делает один явный синтетический запрос через обычный ledger без
  Telegram-отправки и истории участников. Readiness требует новую схему учёта.

## Независимое ревью

Read-only reviewer не нашёл открытых P1/P2. Дополнительная конкурентная проверка:
48 попыток дали 24 уникальные записи и 24 отклонённых дубля. 12 завершённых,
6 неопределённых и 6 незавершённых операций сошлись с расчётом. Накопление более
$12 синтетических резервов не остановило новые операции в observe. Отдельное
соединение подтвердило commit reservation до вызова провайдера.

Для bootstrap/config/operator-проверок независимый набор дал 53 passed.
Сквозной сценарий bootstrap → prepare → synthetic smoke → stats → повторная
подготовка → HTTP readiness прошёл. Контрольная таблица исходной локальной БД
не изменилась; схема Арни возникла только в отдельной БД. Ошибка статистики
не остановила worker и не вывела текст исключения.

Это независимое локальное ревью. Внешнее GitHub Codex review нового commit
не заявляется; прежние внешние ревью относятся к прежним контрольным точкам.

## Параметры и фактический запуск

Для первого запуска выбран `gpt-5.4-2026-03-05`, standard $2.50/input и
$15.00/output за 1M токенов, технические границы 272000/16000, timeout 40s.
[Официальная модель](https://developers.openai.com/api/docs/models/gpt-5.4)
проверена 23 ноября 2026 года. Сумма ledger — расчёт по явно заданным тарифам,
без скидки cached input и без стоимости Railway.

Проверки кода сами по себе не доказывают работающий Telegram или полезность
реальной модели. Развёртывание проводится последовательно: web с созданием
отдельной БД, миграциями и реальным синтетическим AI smoke → SUCCESS/readiness →
настройка Telegram и запуск worker. Актуальные deployment ID, CI и результаты
этой процедуры фиксируются в PR #171, чтобы не выдавать подготовку за запуск.

Согласованность ledger фиксируется на UTC-день. Последующее включение cap в уже
начатом observe-дне требует явной согласованной смены политики либо нового дня;
случайный worker с другой настройкой её не меняет. Технические проверки корректного
usage, модели, доступности БД и источников продолжают действовать.
