# Арни: первичная загрузка существующей истории

## Задача

Загрузить предоставленный владельцем Telegram Desktop JSON в отдельную память
Арни. Сохранить реальные author/message IDs, темы, время создания и последней
правки. Не выдавать экспорт за новые Telegram updates и не запускать ответы на
всю старую переписку. Исходный JSON и реальные идентификаторы не входят в git.

## Границы

- Только явно выбранная группа, подтверждённая текущим Telegram-аккаунтом бота.
- Автор проверяется через `getChatMember`: Desktop `user…` сам по себе не
  доказывает, что это человек. Имена не используются для угадывания личности.
  При HTTP 400/403 доступен точный поиск личности в `getChatAdministrators`
  с `return_bots=true`. Отсутствие совпадения не даёт разрешения на импорт;
  некорректный ответ, timeout, 429 и 5xx этим путём не обходятся.
- Темы выводятся только из явных полей и цепочек до `topic_created`. Неразрешённые
  записи считаются пропущенными. Корень General не подставляется автоматически.
- Обычные тексты сохраняются полностью; rich message получает текстовую проекцию
  с `partial`. Пересланное/цитируемое содержание не становится личным фактом.
- Экспорт содержит последние снимки, а не потерянные версии до каждой правки.
- Отсутствующие в файле сообщения, темы, медиа и удаления не считаются восстановленными.

## Хранение и повторный запуск

Миграция 0017 добавляет `source_archive_imports` (только digest и метаданные) и
`source_origin=historical_import`, `import_batch_id`, nullable `telegram_update_id`.
Идентификаторы обновлений Telegram не подделываются. Тела хранятся в прежнем
архиве и удаляются прежними `forget`/revoke механизмами.

Один parent сохраняется по `(chat_id,telegram_message_id)`. Повтор того же файла
или нового экспорта того же снимка не создаёт новую импортную revision. Автор,
тема и исходная дата неизменяемы. Разные импортные тела с одинаковым временем
правки блокируют весь импорт. Более старая версия не откатывает новую; при
одинаковом времени живая Telegram revision имеет преимущество над импортом.

Порядок блокировок: группа → тема → автор → сообщение. Отключённая группа/тема,
личный отказ, новый период после полного forget и индивидуальные tombstones не
сбрасываются. Новые group-default записи имеют настоящее время регистрации и
не притворяются личным согласием задним числом. Новые jobs/outputs не создаются.

## CLI

В окружении отдельно настроенного Арни:

```bash
python -m app_v2.coach_admin import-history --file /private/result.json --chat-id "$TARGET_GROUP_ID"
python -m app_v2.coach_admin import-history --file /private/result.json --chat-id "$TARGET_GROUP_ID" --apply
```

Первый вызов выполняет те же проверки и записи внутри откатываемой транзакции;
второй атомарно применяет импорт. Вывод содержит только digest и счётчики.

## Временная доставка по HTTPS

Когда production exec недоступен, web содержит закрытый по умолчанию
`POST /admin/history-import`. Для короткого окна оператор задаёт только web:

- `COACH_HISTORY_IMPORT_SECRET`: новый отдельный секрет 32–256 безопасных символов;
- `COACH_HISTORY_IMPORT_SHA256`: SHA-256 точных байтов разрешённого файла;
- `COACH_HISTORY_IMPORT_CHAT_ID`: точная отрицательная группа;
- `COACH_HISTORY_IMPORT_EXPIRES_AT`: обязательный срок в ISO 8601 UTC.

Передать приватный JSON напрямую в HTTPS body, секрет — только в заголовке
`X-Coach-Import-Secret`. Сначала без query (preview), затем `?apply=true`.
Не передавать тело через git, URL, environment variables или логи. Ограничение
8 MiB проверяется потоково. Неверный digest отклоняется до Telegram/DB вызовов.
Без полной действующей конфигурации маршрут отвечает 404.

После загрузки проверить повтор (нулевое число новых записей), поиск и счётчики
архива. Удалить временные настройки и применить конфигурацию web; подтвердить
404 при обращении к закрытому маршруту. Рабочий webhook продолжает работать.
