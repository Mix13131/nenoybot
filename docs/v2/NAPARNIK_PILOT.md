# Арни: отдельный бот с памятью и живым диалогом

Выбранное имя нового Telegram-бота — **Арни**. Имя и обращения задаются через
`COACH_DISPLAY_NAME` и `COACH_ALIASES`; выбранное имя передаётся модели во всех фазах.
Профиль и username нового аккаунта создаются
в BotFather. Это отдельные webhook, worker и логическая PostgreSQL-база в том же
репозитории. Основание — принятый Stage A #169, commit
`d9cab04127da4baadc21563f1975d2fa2df59990`; реализация — PR #171, issue #170.

**Действующая продуктовая политика:** по прямому указанию владельца от 22 ноября
2026 года все возможности включены по умолчанию в настроенной группе. Участнику
не нужно включать хранение, анализ, комментарии или трек отдельными командами;
для публикации собственного обзора в группе не требуется второй запрос.

**Уточнение от 23 ноября 2026 года:** Арни работает во всех группах, куда его
добавили, и во всех их темах. Для этого используется `COACH_GROUP_MODE=joined_groups`.
Группы и темы обнаруживаются при получении сообщений; списки ID и новые команды
для их подключения не нужны. Прежний `configured` режим остаётся совместимым.

Документ описывает код и подключение. Наличие миграций и Draft PR не означает,
что реальный бот уже добавлен, webhook настроен или расходы запущены.

## Поведение в группе

| Возможность | Как работает |
|---|---|
| Первый отчёт | Сразу сохраняется и поступает в анализ. Политика группы применяется до захвата первого сообщения. |
| Самостоятельное участие | Бот видит текущее сообщение, разрешённую историю и контекст своего разговора с автором; выбирает молчание или ответ. Короткая реплика продолжения тоже рассматривается. |
| Форма ответа | Может быть несколько сообщений, вопросов и добровольных предложений. Квоты «один вопрос / один эксперимент / один ответ» нет. |
| Продолжение разговора | Учитываются действительно доставленные ответы бота и собственные сообщения автора. Слова бота помечены как контекст, а не доказательство событий пользователя. |
| Персональный трек | Карточки целей, действий, попыток, результатов и экспериментов. Обзор выбранного периода публикуется сразу по обычной просьбе. |
| Остановка | Личная просьба остановиться или забыть данные имеет приоритет над настройками группы и сохраняется после перезапуска. |
| Архив | Все полученные сообщения и правки в подключённой области сохраняются до ACK webhook независимо от AI, молчания и выключенных автоответов, если сам автор не остановил хранение. |
| Расходы | Общий денежный резерв до каждого AI-вызова; нет дневной квоты числа полезных сообщений. |
| Несколько групп | Один бот, независимые память и очереди каждой группы/темы. Бюджет общий для всего бота. |
| Новая тема | Первое доставленное сообщение регистрирует тему и сохраняется в той же транзакции. Worker обнаруживает её без перезапуска. |

Для каждого нового автора в точной включённой теме создаётся политика
`group_default`, `actor_user_id=NULL`. Это основание настройки группы, а не запись
о якобы выданном человеком согласии. Уже существующие личные настройки никогда
не расширяются автоматически. Миграции сохраняют историю прежних self-настроек.

## Общение обычными словами

Для отчёта и самостоятельного участия обращаться к боту специально не требуется.
Вопрос можно адресовать именем, @username или ответом на его сообщение.
Управляющая фраза должна быть ясно адресована боту: так цитата или чужая реплика
«пока не комментируй» внутри отчёта не меняет настройки автора.

| Пример | Результат |
|---|---|
| «Арни, помоги понять, почему снова откладываю» | Прямой разбор с доступной историей. |
| «Арни, покажи мой трек за 30 дней» | Обзор в этой теме без подтверждения публикации. |
| «Арни, подведи итоги за неделю» | Обзор недели без команд. |
| «Попробовал, не сработало» в ответ боту | Обычное продолжение разговора с контекстом прошлого предложения. |
| «Попробую», «не буду», «попробовал», «не пробовал» в ответ предложению | Отметка своего эксперимента. Если подходящих предложений несколько, бот уточняет словами. |
| «Арни, пока не комментируй» | Автоматические ответы остановлены, трек на паузе; память и прямые ответы сохраняются. |
| «Арни, не запоминай мои сообщения» | Хранение и история выключены; прямое обращение можно разобрать только по текущему тексту. |
| «Арни, забудь мои сообщения» | Живой архив и производная память удаляются; хранение, история, автоответы и трек остаются выключены. |
| «Арни, продолжай» | Возобновляются автоответы и трек, если хранение и история действуют. |
| «Арни, снова запоминай и разбирай» | Явное возвращение всех возможностей после личного отключения. |
| «Арни, удали мой трек» | Удаляются производные карточки, эксперименты и контекст ответов; исходный архив сохраняется. |

Slash-команды остаются совместимыми, но меню команд при настройке пустое, обычный
сценарий их не использует. Старый аргумент `confirm` можно передать по совместимости;
он больше ничего не разрешает и не нужен. В ответах не требуется вводить UUID
экспериментов. Принятие предложения не считается выполнением или успехом.

## Память, источники и доставка

История изолирована по точным группе, теме и автору. Personal memory, другие темы,
чужие сообщения и вложенные Telegram reply/quote тексты не подмешиваются. Архив
охватывает фактически доставленные сообщения; полный старый чат этот runtime
не импортирует. Подписи и ссылки на медиа сохраняются, содержимое
файлов, голос и видео здесь не распознаются. Неизвестные пропуски не объявляются
восстановленными.

В режиме `joined_groups` поддержаны `group`, `supergroup`, General и все обычные
форумные темы. Внутренний `message_thread_id=1` означает General или корень
нефорумной группы, всегда вместе с точным `chat_id`. Обычная ветка ответов без
`is_topic_message=True` относится к корню. При отправке в корень thread ID
опускается; для остальных тем проверяются точные topic ID и `is_topic_message`.
Личные чаты, каналы, guest/business/ephemeral-контексты этим режимом не подключаются.
Анонимные сообщения и сообщения других ботов не используются как история человека.

`my_chat_member` хранит действующее членство и порядок событий. Удаление бота
отменяет задания и все неотправленные части, включая служебные квитанции. Повторное
добавление не возвращает старую очередь и не сбрасывает личные stop/forget или
операторское отключение темы. Запоздавший join не отменяет доказуемо более новые
сообщения. Известные правки ранее принятого источника продолжают обновлять память
после повторного добавления, с проверкой момента самой правки и точного автора.
Проверка членства удерживается через финальную отправку; уже отправляемые байты
Telegram невозможно отозвать задним числом.

Если бот был добавлен до подключения webhook и событие вступления неизвестно,
начальная политика охватывает полученные подписанные обновления, включая очередь
Telegram. Внутренняя нижняя граница Unix epoch служит маркером этого режима,
а не датой подключения или личного согласия. Она позволяет сохранить сообщения,
доставленные не по порядку. Полученное событие удаления всегда сильнее обычного
сообщения; оно не может автоматически восстановить членство. При известном
вступлении учитываются время и update ID, включая несколько событий за секунду.

Весь архив не передаётся в каждый запрос. SQL ищет источники по словам и временным
сегментам по всему доступному периоду. Карточки памяти разрешаются обратно в
доступные оригиналы. Обзор периода раскрывает ограниченность выборки. Фактическая
цитата должна совпасть с исходным текстом; интерпретация остаётся гипотезой.

Первичная AI-фаза извлекает факты и поисковые признаки. Решение молчать или ответить
принимается после выборки истории и диалога. Нет раннего отсечения короткой реплики
по правилу «это не отчёт». Индексация без публикации остаётся отдельным режимом.

Текст доставленного ответа хранится как производный диалоговый контекст, связанный
со всеми показанными модели источниками автора. Он доступен только при действующих
хранении и использовании истории. Отключение истории, забывание, удаление трека или
правка использованного источника очищают соответствующий контекст. Остановка
автоответов сама по себе не стирает разговор; при прямом обращении можно продолжить.
Тексты временной очереди очищаются после обработки или по TTL, отдельно от архива
и разрешённого долговременного контекста. При выключенном хранении прошлый диалог
не используется и новые ответы в долговременную память не записываются.

Все источники, показанные модели, входят в зависимости ответа. Разрешения,
актуальная правка и scope перепроверяются перед каждой AI-фазой и каждой частью
отправки. Части идут по порядку: следующая ждёт подтверждённой доставки предыдущей.
Timeout, отзыв или правка отменяют оставшийся ответ; неоднозначная отправка не
повторяется автоматически. Эксперимент становится `offered` только после доставки
связанной части, а не после генерации текста.

Старое задание не может восстановить трек после удаления: каждая производная запись
проверяет фактическое исходное задание и его lease под блокировкой автора. Ранняя
правка оставляет отметку порядка без текста, чтобы запоздавший оригинал не попал
в AI даже без архива. Это сохраняет исправления предыдущего внешнего ревью.

Технические границы входа и вывода защищают API и память процесса: сообщение
разделяется на части до 4096 UTF-16 единиц, суммарный JSON ограничен 64 KiB,
контекст диалога отбирается в пределах байтового бюджета. Это не квоты числа
вопросов, экспериментов или сообщений.

Удаление живых данных не удаляет уже опубликованные сообщения Telegram и старые
резервные копии. Перед восстановлением копии нужно повторно применить последующие
удаления до запуска worker.

## Подключение отдельного бота

1. Создать новый аккаунт в [BotFather](https://t.me/BotFather), задать имя/username
   и добавить его обычным участником в нужные группы. Администратор для чтения
   и обычных ответов не обязателен: требуется выключенный Group Privacy. Для
   `joined_groups` шаг `setup-telegram` включает `can_join_groups` и
   `can_read_all_group_messages` через `setMySettings` (Bot API 10.5), затем
   перепроверяет их через `getMe`. Остальные настройки бота не меняются. Если
   Telegram ещё не применил чтение в уже подключённой группе, бота нужно заново
   добавить; успех проверяется фактическим обычным сообщением.
2. Выделить отдельную логическую PostgreSQL-базу и отдельные web/worker services.
   Заполнить защищённые переменные по `coach.env.example`: новый токен, DSN,
   webhook secret, HTTPS origin, `COACH_GROUP_MODE=joined_groups`, модель, цены,
   ключ, предел токенов и дневной аварийный бюджет. В этом режиме `COACH_CHAT_ID`
   необязателен и используется только для первоначальной проверки доступа;
   `COACH_TOPIC_IDS` не ограничивает список тем. В совместимом режиме `configured`
   фиксированные chat/topic IDs по-прежнему обязательны.
3. Выполнить `python -m app_v2.coach_admin prepare`. Подготовка сначала исключает
   чужую БД, применяет миграции до 0015 и привязывает новую БД к bot ID.
   В `joined_groups` фиктивные группы, темы и разрешения не создаются.
   Повторный запуск не сдвигает дату уже активированной темы. Настройки участников
   возникают при первом сообщении, без предварительной загрузки списка людей.
4. Запустить отдельные процессы:

   ```bash
   uvicorn app_v2.coach_main:app --host 0.0.0.0 --port "$PORT"
   python -m app_v2.coach_worker
   ```

   `/health` проверяет процесс; `/ready` — идентичность бота и обязательную схему,
   даже до появления первой группы. Worker очищает временные данные и при
   отсутствии активных групп; общий денежный бюджет не делится на группы.
   Импорт приложения не мигрирует БД и не вызывает Telegram или AI.
5. Выполнить `python -m app_v2.coach_admin setup-telegram`, затем
   `python -m app_v2.coach_admin status`. Настройка сверяет bot ID/username и доступ
   к указанной проверочной группе; чужой существующий webhook блокирует запись.
   Принимаются `message`, `edited_message`, `my_chat_member`, проверяется секретный заголовок, накопленные обновления
   не отбрасываются. Статус не печатает сообщения или секреты.
6. Проверить первый обычный отчёт, General, новую тему и вторую группу,
   продолжение ответом на бота, естественный запрос трека, молчание на обычную
   болтовню, остановку и забывание. Участники не проходят
   личное включение или подтверждение публикации.

При заполненной основной конфигурации `COACH_ENABLED` и `COACH_AI_ENABLED`
по умолчанию включены. Пустая среда остаётся неактивной и безопасно импортируется.
Отсутствие финансовых параметров при включённом AI даёт ясную ошибку конфигурации.
`COACH_ARCHIVE_POLICY` по умолчанию — `until_author_deletes`.

Операторские выключатели остаются: `COACH_AI_ENABLED=0` останавливает новые AI-вызовы
с сохранением архива; `COACH_ENABLED=0` останавливает новый архив и анализ, оставляя
обработку остановки и удаления. Явно выключенная тема не включается при повторном
prepare. Действующий runtime НеНоя не использует эту новую конфигурацию.

## Расходы и проверка качества

Используются только `COACH_*` переменные. Точный model ID, тарифы, предел входа и
выхода, дневной денежный бюджет задаются явно; цены не угадываются. До каждого
запроса PostgreSQL резервирует максимальную настроенную стоимость для всех фаз
вместе. Известный usage уменьшает резерв; timeout, crash и неизвестный usage его
сохраняют. Повтор той же operation ID не оплачивает скрытый retry. Такой резерв
может остановить запрос раньше фактического исчерпания бюджета — это защита от
аварийного расхода, а не лимит количества разговоров.

Responses API вызывается без инструментов, с `store=false`, строгой JSON schema,
`truncation=disabled`, output token bound и без автоматических повторов. Тарифы
синтетической модели из тестов не являются ценами провайдера.

Синтетические тесты доказывают механику архива, натуральных обращений, нескольких
сообщений и экспериментов, источников, продолжения диалога, удаления и гонок.
Они не измеряют уместность или полезность реальной модели:
`real_model_quality_measured=false`. Прогон выбранной модели и реального Telegram
остаётся практической частью подключения; действующих credentials здесь нет.

Источники: [Telegram Bot API](https://core.telegram.org/bots/api),
[privacy mode](https://core.telegram.org/bots/features#privacy-mode),
[General и форумные темы](https://core.telegram.org/api/forum#interacting-within-topics),
[setMySettings](https://core.telegram.org/bots/api#setmysettings),
[Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create).
