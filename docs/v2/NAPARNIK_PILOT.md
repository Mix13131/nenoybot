# Напарник: полный изолированный пилот

Рабочее имя нового Telegram-бота — **Напарник**. Имя и обращения задаются через
`COACH_DISPLAY_NAME` и `COACH_ALIASES`; профиль и username нового аккаунта создаются
в BotFather. Это отдельный запуск из того же репозитория, с отдельными webhook,
worker и логической PostgreSQL-базой. Основание — принятый Stage A PR #169,
commit `d9cab04127da4baadc21563f1975d2fa2df59990`; расширение — issue #170.

Документ описывает реализованный код и процедуру подключения. Создание документа,
миграций и Draft PR само по себе не подключает группу и не запускает расходы.

## Возможности

| Часть | Реализованное поведение |
|---|---|
| Архив | Все полученные разрешённые сообщения и правки в заданных темах, независимо от решения ответить и работоспособности AI. Коммит до ACK webhook. |
| Согласия | Участник сам включает хранение, анализ истории, автоматические комментарии и ответы по запросу. Уведомление должно быть фактически отправлено до принятия положительного согласия. |
| Разбор | Автоанализ выбирает молчание, один вопрос или один добровольный обратимый эксперимент. Прямое обращение работает и без долговременного хранения. |
| Смысловая память | Карточки целей, планов, попыток, действий, результатов и экспериментов с проверяемыми источниками. Фактические цитаты должны совпасть с исходным текстом; интерпретации помечаются гипотезами. |
| Трек | Индексация при активном треке; обзор за заданный период по запросу. Отдельное подтверждение публикации в группе. Принятый эксперимент не считается выполненным. |
| Расходы | Единый PostgreSQL-реестр резервирует максимальную стоимость до каждого вызова, затем учитывает известный usage. Это денежный аварийный предел, а не квота полезных ответов. |
| Отправка | Повторная проверка всех использованных источников, версии согласия, текущей правки и scope непосредственно при отправке. Неоднозначный сетевой результат не повторяется автоматически. |

История извлекается только по точным группе, теме и автору. Между темами и людьми
нет автоматического объединения; Personal и обычная Group memory не используются.
Предварительная оценка текущего отчёта определяет его пригодность для разбора.
Для пригодного отчёта окончательное решение молчать или ответить принимается
после выборки разрешённой памяти: тихий текущий эпизод может оказаться значимым
в контексте прежних действий. Индексация без публикации остаётся одной фазой.
В этом runtime отсутствует обычная сырая очередь НеНоя: неподключённые сообщения
не попадают в `events/messages/outbox`. Для дедупликации остаются минимальные
технические идентификаторы доставки, без текста и raw Telegram payload.

## Что означает «память»

Архив хранит разрешённые источники до удаления автором или отключения хранения.
Он не ограничен 30 днями. Telegram Bot API не даёт этому коду полную старую историю:
накапливаются сообщения, реально доставленные после активации и согласия.
Неизвестные пропуски доставки не объявляются заполненными. Подписи и ссылки на
медиа сохраняются; содержимое файлов, голос и видео здесь не распознаются.

Анализ не передаёт весь архив в каждый запрос. SQL выбирает ограниченное число
источников по всему разрешённому периоду: по найденным словам или равномерным
временным сегментам. Карточки памяти дополняют выборку, но каждый раз разрешаются
обратно в доступные оригиналы. Ответ сообщает размер выборки, доступный объём и
ограничения. Это текстовый поиск и источниковые карточки без отдельной векторной БД.

Доказательная зависимость ответа включает **все источники, показанные модели**,
а не только те, которые она процитировала. Правка/удаление источника или изменение
согласия отменяет подготовленную производную публикацию. Если текущий прямой
запрос разрешён лишь временно, он не превращается в долговременную карточку или
эксперимент через смешивание с разрешённой историей.

Каждая запись производной памяти дополнительно проверяет действующее задание
под общей блокировкой участника. Анализ, начавшийся до удаления трека, не может
записать его заново после удаления. Для полученной раньше оригинала правки
сохраняется техническая отметка порядка без текста: запоздавший старый запрос
не попадёт в AI даже при выключенном архиве и после перезапуска. Срок временной
обработки ограничивает только новые AI-задания; разрешённый архив не обрезается.

## Команды участника

Команды отправляются в подключённую тему группы. Разрешения относятся только к
отправителю этой темы. Администратор не может выдать согласие за другого человека.

| Команда | Действие |
|---|---|
| `/help`, `/privacy` | Уведомление о хранении, анализе и видимости ответов. |
| `/settings`, `/status` | Текущие личные разрешения. |
| `/archive_on`, `/archive_off` | Включить хранение; отключить и очистить живые тексты архива. |
| `/history_on`, `/history_off` | Разрешить/запретить использование истории для анализа. |
| `/direct_on`, `/direct_off` | Разрешить/запретить ответы на собственные запросы. Можно без архива. |
| `/auto_on`, `/auto_off` | Включить/выключить автоматический анализ и самостоятельные комментарии. Для включения уже нужны отдельные согласия на архив и историю. |
| `/ask текст` | Запросить разбор собственного текста. Также работают адресное имя, @username и ответ на сообщение бота. |
| `/track_start`, `/track_pause` | Включить сбор персонального трека / поставить его на паузу. |
| `/track 30` | Запросить трек за 30 дней; бот сначала объясняет, что ответ будет виден группе. |
| `/track 30 confirm` | Подтвердить публикацию трека в этой группе. |
| `/review 7`, `/review 7 confirm` | Такой же отдельный запрос обзора за неделю. |
| `/accept ID`, `/decline ID` | Принять или отклонить конкретный предложенный эксперимент. |
| `/tried ID`, `/not_tried ID`, `/close ID` | Зафиксировать собственный отчёт о попытке/отсутствии попытки либо закрыть эксперимент. |
| `/stop` | Выключить автоматические комментарии и поставить трек на паузу. Отдельное право ответов по запросу сохраняется. |
| `/track_delete` | Удалить производный трек и эксперименты, выключить трек. Исходный архив сохраняется. |
| `/forget` | Удалить свой архив и производные записи этой темы. Для запрета будущего хранения дополнительно `/archive_off`. |

Сначала `/privacy` и получение уведомления, затем нужные команды согласий.
Первое включение до доставки уведомления только возвращает уведомление; повторное
включение после доставки принимает личный выбор. Команды с `@username` принимаются
только для этого бота. Пересланная, процитированная или отредактированная команда
не выдаёт согласие.

ID эксперимента присутствует в сообщении с предложением. До успешной отправки
сохраняется внутренний статус `prepared`; подтверждённая отправка переводит его
в `offered`. `accepted` означает только согласие попробовать; `tried_self_reported`
означает сообщение участника о попытке, без заявления об объективном успехе.
При отзыве или неоднозначной отправке предложение не объявляется доставленным.

Удаление касается живых данных этого runtime. Уже опубликованные сообщения
Telegram и прежние резервные копии автоматически не удаляются. Восстановление
копии требует повторного применения последующих удалений до включения worker.

## Отдельный запуск

1. Создать новый бот в [BotFather](https://t.me/BotFather), выбрать имя/username,
   добавить его в нужную существующую группу. Доступ к обычным сообщениям нужен
   для архива: подходящий статус администратора либо отключённый privacy mode.
   Команда настройки проверяет `getMe`, `getChat`, `getChatMember`; конкретные ID тем
   дополнительно проверяются доставленным тестовым сообщением.
2. Создать отдельную логическую PostgreSQL-базу и отдельные web/worker services.
   Заполнять их защищённые переменные по `coach.env.example`. Не копировать рабочие
   токен, webhook, DSN и переменные запуска НеНоя. В базе не должно быть другого
   приложения: `prepare` проверяет это до миграций и привязывает базу к bot ID.
3. Указать точный `COACH_CHAT_ID`, явный список `COACH_TOPIC_IDS`, webhook secret,
   публичный HTTPS origin и выбранную политику `COACH_ARCHIVE_POLICY=until_author_deletes`.
   Не создавать согласия участников SQL-скриптом.
4. Подготовить новую базу:

   ```bash
   python -m app_v2.coach_admin prepare
   ```

   Повторная подготовка идемпотентна и не двигает дату начала уже созданного scope.
   Обычный deploy entrypoint НеНоя для этого сервиса не используется.
5. Запустить web и worker отдельными командами:

   ```bash
   uvicorn app_v2.coach_main:app --host 0.0.0.0 --port "$PORT"
   python -m app_v2.coach_worker
   ```

   `/health` проверяет процесс; `/ready` — привязку новой базы и необходимые таблицы.
   При импорте приложения нет миграций, настройки Telegram или AI-запросов.
6. На новом боте явно настроить webhook и меню:

   ```bash
   python -m app_v2.coach_admin setup-telegram
   python -m app_v2.coach_admin status
   ```

   Настройка сначала сверяет bot ID/username и доступ к группе. Если у токена уже
   задан webhook другого развёртывания, настройка блокируется до любой записи:
   она не перехватывает действующего бота. Webhook принимает
   только `message`/`edited_message`, использует секретный заголовок и не отбрасывает
   накопленные обновления. Консольный статус не печатает сообщения или секреты.
7. После проверки параметров включить `COACH_ENABLED=1`. Для AI отдельно заполнить
   модель, ключ, тарифы, границы токенов и дневной аварийный предел, затем
   `COACH_AI_ENABLED=1`. Участники проходят личное включение непосредственно в теме.

Документация Telegram: [webhook и методы Bot API](https://core.telegram.org/bots/api),
[privacy mode](https://core.telegram.org/bots/features#privacy-mode).

## Финансовая конфигурация

Runtime использует только `COACH_*` переменные. Внутренний gateway также имеет
низкоуровневый конструктор; параметры основного НеНоя не подхватываются.

| Переменная | Значение |
|---|---|
| `COACH_AI_MODEL` | Точный идентификатор явно тарифицированной модели. Ответ с другим model ID блокирует дальнейшие вызовы этого дня. |
| `COACH_AI_EMERGENCY_DAILY_USD` | Общий аварийный предел на UTC-день для анализа, индексации, генерации и трека вместе. |
| `COACH_AI_INPUT_USD_PER_MILLION` | Проверенная цена миллиона входных токенов. |
| `COACH_AI_OUTPUT_USD_PER_MILLION` | Проверенная цена миллиона выходных токенов, включая reasoning. |
| `COACH_AI_MAX_INPUT_TOKENS` | Верхняя граница входа, используемая для резервирования. |
| `COACH_AI_MAX_OUTPUT_TOKENS` | Передаваемый провайдеру предел генерации и reasoning. |

Тарифы и предел не угадываются из названия модели. До вызова проверяется
консервативная оценка входа, включающая prompts и JSON schema; резервируется полная
настроенная максимальная стоимость. Известный usage уменьшает резерв до учтённой
стоимости. Неизвестный usage, timeout и crash сохраняют полный резерв. Одна
operation ID не может повторно оплатить скрытый retry. Конкурентные workers
резервируют общий остаток под блокировкой строки PostgreSQL.

Такая защита может остановить новый запрос, чей максимальный резерв не помещается
в оставшийся бюджет, даже если фактический короткий ответ стоил бы меньше. Это
следствие защиты расходов. Искусственных правил «не больше N полезных ответов в
день» нет. Цены, токеновые границы и стоимость инфраструктуры необходимо проверить
перед включением реального ключа; синтетические тестовые тарифы не являются ценами
провайдера. Предел покрывает только вызовы через этот runtime и его базу.

Responses API вызывается без инструментов, с `store=false`, строгой JSON schema,
`truncation=disabled`, ограничением output и без автоматических повторов.
Документация: [Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create).

## Проверка и границы готовности

Автоматические тесты используют вымышленные авторов, сообщения, токены и модель.
PostgreSQL-тесты проверяют реальные транзакции, миграции, гонки согласий, денежные
резервы, очереди, отмену ответа после правки/отзыва и отсутствие дубликата после
неоднозначной отправки. Сквозной сценарий проверяет весь путь через отдельный
runtime, не обращаясь к Telegram и платному AI.

Набор `tests_v2/fixtures/coach_synthetic_quality.json` и проверки engine фиксируют
механику: источники, границы режима, один вопрос/эксперимент, молчание, отсутствие
заявления о повторяемости на копиях одного эпизода. Ответы fake-модели не доказывают
уместность или полезность реальной модели. Перед включением самостоятельных
комментариев необходимо прогнать выбранную модель на этих сценариях и оценить
ответы людьми. Пока этот прогон не выполнен, пилот остаётся Draft.

При подключении проверяются: обычное сообщение и его правка в разрешённой теме;
молчание без согласия; получение privacy notice; личные grants; AI outage при
сохраняющемся архиве; один ответ по запросу; review с подтверждением; эксперимент
и self-report; `/history_off`, `/stop`, `/forget`; изоляция соседней темы и автора.

`COACH_AI_ENABLED=0` останавливает новые AI-вызовы, сохраняя разрешённый архив.
`COACH_ENABLED=0` останавливает новый архив и анализ, оставляя команды управления
и удаления. Отключение конкретного scope отменяет его ожидающие анализы и ответы.
Новая установка не меняет текущий Telegram webhook НеНоя или его службы.
